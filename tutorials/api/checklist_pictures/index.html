API TUTORIAL – CHECKLIST PICTURES ​

Intro ​

This page shows how to download the pictures taken for the checklist tasks of a panel, and how to know which panel and which task each picture belongs to.

INFO

The base URL for the produuz.it API V2 is: https://back.produuz.it/api/v2/

Find pictures by panel, never by file name

New pictures are named after their panel (see File names). Pictures uploaded before that change keep the name they had. Use the filters below to find a panel's pictures: they return old and new pictures alike. A search on the file name finds only the new ones.

How pictures are stored ​

Every panel (assembly or module) that starts production gets one proof, which holds its checklist. The pictures of the checklist are in a file package named checklist that belongs to that proof, not to the panel itself. That is why ?assembly=<uuid> on the packages list does not return them: use the filters through the proof.

Pictures of one panel ​

Endpoint: https://back.produuz.it/api/v2/cloudstorage/packages/?proof__assembly=<panel uuid>&name=checklist

  • Method: GET.
  • For a module, use ?proof__module=<module uuid>.
  • Response: A list with the panel's checklist package, or an empty list when the panel has no pictures yet.

Pictures by unit ID ​

The unit ID is the customer's own number for a panel, read from the IFC by the project's parsing setup.

Endpoint: https://back.produuz.it/api/v2/cloudstorage/packages/?proof__unit_id=A12-03&proof__project=<project uuid>&name=checklist

  • Method: GET.
  • It returns the checklist packages of every assembly and module with that unit ID.
  • Unit IDs repeat across projects, so add proof__project to stay in one project.
  • Panels created before unit IDs were read from the IFC have no unit ID. Find those by their uuid with proof__assembly.

All the pictures of a project ​

Endpoint: https://back.produuz.it/api/v2/cloudstorage/packages/?proof__project=<project uuid>&name=checklist

  • Method: GET.
  • One package per panel that has pictures. Each package's proof says which proof it belongs to, and GET records/rcps/?project=<project uuid> gives the panel of each proof.

File names ​

A new checklist picture is stored under a name that says which panel it shows, so a file downloaded on its own can still be matched to its panel:

<design>_<unit-id>_<station>_<task>_<date>_<random>.<ext>
<design>_<unit-id>_<station>_<task>_<date>_<random>.<ext>

Example: WE-0412_A12-03_Framing-1_Check-studs_2026-11-03T08-42-15_k3f9.jpg

PartWhat it is
designThe panel's design name.
unit-idThe panel's unit ID, or the first 8 characters of its uuid when it has none.
stationThe production station the picture was taken at.
taskThe checklist task.
dateUpload time in UTC.
random4 characters, so two pictures never share a name.

Each part keeps only letters, digits and -, so a _ always separates two parts, and long parts are cut. The name is meant for people reading a folder of downloaded files. To find a picture in the API, use the filters above: the name is never rewritten after upload, so it keeps the design name and unit ID the panel had at that moment.
