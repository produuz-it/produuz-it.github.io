Upload Files ​

Files for each project are uploaded in Files, in the project menu under Designs:

Click Upload. The dialog starts with what the files are, on the left: Automatic, Project, Module, Assembly or Documents. With Automatic, the default, there is nothing else to choose: drop, paste or browse any mix of files, and each one goes to its file group by itself. See Auto-detect. Pick a level to choose the file group yourself, on the right: the list holds Auto-detect at that level and the groups of that level. Pick Documents for details, documentation and specifications, which have no level. Then drop or browse the files: the list under the drop zone says where each one goes. Click Upload. On a phone, the choice on the left is a list too. The dialog never asks a type: a design gets its type when it is analysed, or by hand. See The type of a design.

When the upload ends, the dialog shows how many files were uploaded and an Update designs button. Nothing runs on its own: you decide when the designs are updated, for example after the last of several uploads.

The file groups, by level:

  • Auto-detect: what Automatic does, and the first group at each level. Each file is sorted by its name. See Auto-detect.

  • Assembly Files: Assembly IFCs (.ifc), Assembly BTLx (.btlx, only when BTLx designs are switched on for your company), Extra Assembly IFCs (.ifc), Assembly drawings (.pdf), Machine Files (.jjs, .wup, .btl).

  • Module Files: Module IFCs (.ifc), Extra Module IFCs (.ifc), Module drawings (.pdf).

  • Project Files: Project IFCs (.ifc), External IFCs (.ifc), Project drawings (.pdf).

  • Documents: Details (.pdf), Documentation (.pdf, .jpeg, .png), Specifications (.pdf, text). Documentation and specifications can also be added as text with the Add as text switch.

The file name decides which design a file belongs to:

  • IFCs: used for the 3D viewer, BoMs and machine files. The system reads them with the project's IFC Parsing Setup. The file name without extension is the design name. Example: "PNL30-25.ifc" belongs to design "PNL30-25".

  • Extra IFCs: the design name is the part before the first " - ". Example: "PNL30-25 - Installations.ifc".

  • Machine files: the file name without extension is the design name. Example: "PNL30-25.btl".

Full Project IFCs

You can also upload full project IFCs and the system can split them into one IFC per design. Upload them in the Project IFCs (.ifc) group. The file name does not matter. Example: "OlaraAvenue15.ifc".

  • Drawings: .pdf file format. They are shown in the viewer. The name of an assembly or module drawing must follow one of your company's drawing name templates. The one every company starts with is "Merk DESIGN_NAME - DRAWING_NUMBER - DRAWING_NAME.pdf", where the word "Merk" at the start is optional. Example: "Merk PNL30-25 - 1 - Zone 0 MAIN VIEW.pdf". A drawing whose name follows no template is not uploaded: the dialog names the file and the templates of your company. Project drawings are read the same way when their name follows a template, and are uploaded when it does not.

  • Details and documentation: .pdf file format. Also shown in the viewer. The file name without extension is the detail name that the system looks for in drawings. Example: "V-12.pdf". Documentation files are linked to every design of the project.

Full Project PDFs

In design mode, the viewer shows a "General Arrangement" entry at the top of the list. It opens the full project IFCs in 3D and the drawings uploaded as Project drawings (.pdf), one button per drawing.

  1. The list filter set to Design.
  2. The General Arrangement entry.
  3. The designs, with their revisions. Older revisions are red.
  4. 3D and one button per project drawing.

Auto-detect ​

Auto-detect is what Automatic does, and the first entry of the file group list at each level. Automatic gives each IFC and drawing its level by your company's levels and types detection; at a level, every IFC and drawing is of that level. The dialog remembers your last choice on that browser. Then drop drawings, details, specs, documents and IFCs together. Before anything is uploaded, the dialog lists every file with what it was recognised as; change the level and the list changes with it. Nothing is read from inside a file: each one is sorted by its name and the level, by the first of these that applies:

  1. A new version of a file already in the project goes where the earlier version went, with the same design.
  2. IFCs go to Project IFCs, Module IFCs or Assembly IFCs, by the level. With Automatic, the level is the one of the first rule that matches the file name, or the Otherwise level when none does. The file name without extension is the design name.
  3. BTLx files go to Assembly BTLx, when BTLx master files are on for your company.
  4. Drawings whose name follows one of your drawing name templates go to Project drawings, Module drawings or Assembly drawings, by the level, with the design they name. With Automatic, the rules are matched on that design name, Merk M12 - 1 - Frame.pdf on M12, and the Otherwise level applies when none matches. The design does not have to exist yet: the drawing is attached when Update designs makes it, as a drawing uploaded to its own group is.
  5. Details, specs and documents are recognised by your company's other files detection.
  6. Anything else goes to the Otherwise group of the other files detection, Doc to start with.

So every file gets a group. To change one later, delete it and upload it again in the file group you want.

When you pick a level yourself, upload files of one level at a time: a panel IFC uploaded at Project becomes a Project IFC, and Update designs splits it. Extra IFCs, External IFCs and machine files are not recognised: pick their file group yourself, unless they are a new version of a file already in the project.

When the upload ends, the dialog also says what was found, for example 3 drawings · 1 detail · 1 spec · 1 document · 2 model files. Auto-detect does not start Update designs: you still decide when the designs are updated.

Table of uploaded files ​

The table of files is shown below the upload summary. The summary counts the files, how many are linked to a design and how many name a design that does not exist, and shows the project's parsing setup with a link to change it.

  1. Upload and Update designs. The number on Update designs counts the pending files.
  2. The summary: files, files linked to a design, and files that name a design that does not exist.
  3. The search, Only latest versions and Only design files.
  4. The design of each file. A full IFC shows how many designs came out of it; an orange chip names a design that does not exist.
  5. The status of each file, explained below.

Use Filename search to filter the table, and Only latest versions to hide older versions of files uploaded again with the same name. Tick Only design files to list only the IFC and BTLx files. Select rows to delete, download or update designs from several files at once. The Design column shows the design each file is linked to.

Each file shows one status. The orange ones are pending: the next Update designs takes them in.

StatusDescription

The project menu shows the same number on Files from any page of the project, so you see that files are waiting without opening this view. While an update runs, the menu shows a spinner there, and a red mark if it failed.

An older export uploaded after a newer one ​

Each IFC records the time it was exported, as written in the file. The time is read when the design made from the file is analysed (a building IFC when it is split). A new version of a file gets the next version number, in the order of the uploads, and a design takes the newest version. So an old export uploaded again by mistake would become the design's new revision.

When a version was exported before an earlier version of the same file, a warning icon sits next to its status. Hover it to see both export times, for example Exported 2026-10-28 14:02, before version 2 of this file (exported 2026-10-30 09:15). Check that the right export was uploaded.

The same warning is in the file's Messages: click its status to open them. They also hold the warnings of a split. On a phone, tap the row, then its status.

The warning does not block anything. The design shows it too, see The model of this revision was exported before the previous one. What to do:

  1. Check which export you uploaded, for example by the export time in your modelling program.
  2. If it is the wrong one, delete that version in the table (⋮ → Delete), or upload the right export with the same name. The right export becomes a newer version, and the next Update designs gives the design a new revision from it.
  3. If the older export is the one you want, do nothing.

Files uploaded before this check existed have no export time and are not compared. BTLx files are not checked.

Set category ​

The Type column shows the file group of each file by its name. When Auto-detect chose it, the group has a wand mark; hover it to see why, for example Drawing of W10, Level rule: W, or Sorted by the level chosen at upload. A file still waiting in Auto-detect shows Auto-detect, and its state in the Status column.

A file left in Auto-detect by an upload made before every file was sorted shows Choose category. It is left out of Update designs until it has one, and the project menu counts it on Files.

Set category, in the row menu or in the selection bar for several files, gives a file group to the files still waiting in Auto-detect, the ones that show Choose category. A file that already has its group keeps it, and Set category is not offered on it. A drawing must follow one of your drawing name templates to get a drawing group.

The table has no design type column: a design gets its type from its analysis or by hand, never from its files.

Upload detection ​

Upload detection says how your company names the files it uploads. Open Projects Settings in the Settings section of the company menu, and expand Upload detection, just below Phase templates.

The card has three blocks, in this order.

Levels and types detection gives each IFC and drawing its level for the Automatic level of the upload dialog, and each design the type it gets when Update designs creates it. Each rule has a level (Project, Module or Assembly), a type, a type of match (Match full word, Match prefix or Contains word) and a value. Case does not matter, and the rules are tried from the top:

  • for the level, on the file name of an IFC, without its extension, and on the design name of a drawing; the first rule that matches gives the level;
  • for the type, on the design name, among the rules of the design's level; the first that matches gives the type.

Generic gives the level only, and a Project rule has no type. The last row, Otherwise, is the level and type when no rule matches: Assembly and Generic to start with. A company that makes one kind of panel only picks that type there and writes no rule. For example:

#LevelTypeMatchValue
1ModuleModule unitMatch prefixM
2AssemblyTimber exterior wallMatch prefixBU
3AssemblyTimber interior wallMatch prefixBI
4AssemblyTimber floorMatch prefixVL
5AssemblyTimber roofMatch prefixHD
6Otherwise AssemblyGeneric

Drawing name templates say how a drawing's name gives its design and drawing number. A template is written with these placeholders:

In a templateMeans
{design}The design name. Required.
{number}The drawing number. Required.
{name}The drawing name. Optional.
*Any text.

Everything else in a template must be in the name as written. A template is compared with the whole file name without its extension, and case does not matter. Templates are tried from the top, and the first that matches wins. Drag them to change the order.

Ignored words are left out at the start of the name, before the design.

Every company starts with the templates {design} - {number} - {name} and {design} - {number} and the ignored word Merk, which is what every drawing upload expected before. Add a template when your drawings are named another way:

TemplateFile nameDesignDrawingDrawing name
{design} - {number} - {name}Merk D10 - 1 - Frame.pdfD101Frame
{design} - {number}D10 - 2.pdfD102
{design}_{number}D10_3.pdfD103

Type a name in Try a file name, to the right of the rules (below them on a phone), to see how it is read before you save: the design, the drawing number, the level and the type it gets, for example · level Assembly · type Timber exterior wall (level rule 2), or (fallback) when an Otherwise row decided.

Other files detection recognises details, specs and documents for Auto-detect. Each rule has a file group (Detail, Spec or Document), a type of match (Match full word, Match prefix or Contains word) and a value, compared with the file name without its extension. The first rule that matches wins, for example DET with Match prefix for details and Bestek with Contains word for specs. The last row, Otherwise, is the group of a file nothing else recognises: Doc to start with.

Update designs ​

Update designs brings the project's designs in line with its files. It runs three steps, in this order:

  1. Split building IFCs: Project, Module and External IFCs become one IFC per panel (and per module).
  2. Create and revise designs: designs are created and get the files that belong to them.
  3. Link details: drawings and IFCs are scanned for detail names.

There is one button, Update designs, at the top of the table:

  • With no file selected it works on every file of the project and does what is pending in them: the files with an orange status. The button shows how many there are. This is the usual way after an upload.
  • With files selected in the table it says Update designs from N files and works on those files only, and always does them, even if they were already done: for example to split a file again after deleting its outputs or after a fix, or to update only some designs. A Module IFC made by a split is split again too when you select it.

It opens a dialog that shows what will happen before anything runs.

  1. What the update works on: all the files, with how many are pending, or the selected ones.
  2. The splitting engine, see Split building IFCs.
  3. What each step will do: the files to split, the designs that are created or get a new revision, and the unbuilt units that move to the new revision.
  4. The plan in one sentence, and the button. When units move, the button says how many.

Each step has a switch. With selected files, every step that can take one of them starts on. With no selection, a step starts on when it has pending files, and off when it has none; the step then says what it already did, for example Nothing pending · 2 building IFCs already split. You can always turn it on: it then takes the files it already did again. This is what you need after changing the IFC Parsing Setup, when the building IFCs must be split again. To do only some files again, select them in the table. The settings are folded under the step, and the dialog opens with the settings of the project's last update.

While an update runs, the banner lists the three steps: a spinner on the one running, with its progress, a check on the ones done, and an empty circle on the ones waiting.

While the update runs, a banner above the table shows the step and its progress. When it ends, the banner shows how many designs are new or revised, which files could not be split, and the split warnings. The table, the designs and the counts reload on their own. Close the banner when you have read it.

Only one update runs in a project at a time. Production Counts stays open while the IFCs are split, and is locked while designs are created and revised, until the update ends: that step moves units and counts to the new revisions.

The update stopped responding

An update reports its progress every minute. If it reports nothing for 30 minutes, the banner says The update stopped responding and offers Mark as stopped, which unlocks its files so you can start a new one. If it was still running after all, it finishes anyway.

Split building IFCs ​

Full IFCs are split into one IFC per design. The new files are added to the project as Assembly IFCs (and Module IFCs) and can be downloaded. The split also stores the quantity of each design and the phases and batches found in the IFC, so they are available in Production Counts. How assemblies are found in the IFC depends on the IFC Parsing Setup.

The split is available when the IFC splitter module is enabled for your company. The designs of the split files are created in the next step of the same update.

There are two engines:

  • Standard, recommended for Tekla, Revit, hsbCAD, cadwork, Vertex and AutoCAD Architecture, takes out everything the file holds: the modules, the assemblies in them and the assemblies at the project root. To leave modules or assemblies out, use the Module filter and the Assembly filter of the IFC Parsing Setup.
  • Legacy, recommended only for some older Tekla and Revit export setups, makes one IFC per assembly. It cannot split a parsing setup that finds assemblies by a part property.

A Module IFC you upload is split like a project IFC: it is a partial revision of the project, for example one module exported again. The file is the design file of its own module, so the split does not write that module out again: it takes out its assemblies, and any other module the file holds. The update makes the design of the module and of its assemblies. Without the splitter module an uploaded Module IFC is only a design file. Every Module and Assembly IFC, uploaded or made by a split, goes to the designs. When several files name the same design, the design takes the one exported last, by the time written in the IFC; of the versions of one file, the highest. If you upload a new version that was exported before the previous one, the Files table and the Designs list warn you: it is probably an old export uploaded by mistake. See An older export uploaded after a newer one.

A project keeps the engine it was split with. A project that was never split starts on Standard. If you switch engine on a project that was already split, the dialog warns you: design names can differ between engines, and designs that change name are created again.

Settings

☑️ Skip standard library names Does not create IFCs for designs that already exist in the standard library.

If a file cannot be split, the other files go on, and the designs of the failed file are left as they were.

Create and revise designs ​

The system collects the IFCs, drawings and machine files and creates "design" objects.

  • A list of design names is built from the file names of assembly and module IFCs, drawings and machine files.

  • Each file is attached to its design. All the documentation files are linked to every design, so they are always available.

  • When a design gets a new file, it gets a new revision, and its units that are not built yet move to the new revision.

Units are not created here. Create them in Production Counts with Update production.

The model of this revision was exported before the previous one ​

A design remembers when the model of each revision was exported. It is read when the design is analysed. The design panel shows it after the revision, · Exported 2026-10-30 09:15, and on each row of Other revisions. Revisions made before this was recorded show no export time.

When a new revision's model was exported before the model of the revision before it, the design gets a warning icon:

  • in the Designs list, after the design's name;
  • in the design panel, after Exported ….

Hover it to see both times: The model of this revision was exported before the previous revision's (2026-10-28 14:02, previous 2026-10-30 09:15). Nothing is stopped: the revision exists and its unbuilt units moved to it.

What to do: open the design and compare the export times of its revisions. If the new revision came from the wrong export, upload the right one and run Update designs again: the design gets a new revision from it, and its unbuilt units move to it. See An older export uploaded after a newer one.

The type of a design ​

Each design has a type. An assembly design is Timber exterior wall, Timber interior wall, Timber roof, Timber floor, Timber panel, Steel wall, Steel cage or Concrete slab. A module design is Module unit. Production lines say which types they make. See Production Lines.

No file brings a type. A design gets its type in these ways:

  • From its name, when it is created, by the Levels and types detection rules of Upload detection. A design no rule of its level matches gets the Otherwise type when the Otherwise level is its level, and Generic otherwise. A new revision keeps its type; one that is still Generic gets the type its name gives, so rules you add later reach the next revision.
  • Corrected when it is analysed, by the Assembly type correction and Module type correction rules of the IFC Parsing Setup, when one matches. A design no rule matches keeps its type. These are not needed when your design names follow your level and type rules.
  • By hand, with the Type in the design's details and its edit button, or with Set type in the Designs list.

A type chosen by hand is never changed by the analysis, by a new revision or by the rules. A subassembly gets its type from its panel's analysis. Timber panel is a timber panel of none of the four kinds: designs made before the four types existed have it.

The type also decides how a design is analysed: a design typed Steel cage is analysed as a steel cage. When the rules or a person change a design to or from Steel cage, it is analysed again.

Each type has its own icon, shown before the design's name in the Designs and Constructibles lists, in their details and in the viewer's list. A unit shows the icon of its design's type.

Set type ​

In the Designs list, Set type sets the type of one design (in the ⋮ menu of its row) or of the selected designs (in the bar above the list). On a phone, tap Select, pick the designs, and Set type is in Actions.

The window has one type list per level: Assembly type for the assembly designs and Module type for the module designs. It opens on the type the designs share, and on nothing when they differ. Save sets the type as a choice made by hand. A subassembly in the selection is listed in the window and keeps its type.

Settings

☑️ Keep revision numbers Designs keep their revision number when they get new files.

☑️ Draw from IFC Generates drawings from the IFC of each design, with the default set of views.

Link details ​

Details can be automatically detected in IFCs and PDF drawings. Found detail names are linked to the design and then shown in the viewer. Only the drawings that were not scanned yet are scanned; when a new detail is uploaded, every drawing is scanned again for it. In a project with no details and no specs, drawings are not scanned and do not count as pending.

Settings

☑️ Scan drawings Drawings are scanned to find detail and specification names, and details are scanned to find specification names. On by default.

☑️ Scan IFCs IFCs are scanned for detail names in the property "DET_NUMBER".

If your detail names can't be detected by the system, you may have a rasterized export, or a rasterized font in a vectorized export, such as the well known issue with AutoCad.

Analysis (prepare the viewer) ​

The analysis starts automatically when a design gets a new IFC, for example after Update designs. It also sets the type of the design from the IFC Parsing Setup's rules, and reads when its model was exported. There is no button for it in the Update designs dialog. If the company setting Launch analysis automatically is off, or you need to run it again, select the designs in Designs and click Force analysis. The Analysis column of the designs table shows the status of each design.

Slow task!

⚠️ This operation takes time. It runs many heavy computations and database tasks.

  • IFC geometry is analyzed to find the rotation and translation matrices (orientation of the panel in the world coordinate system).

  • Panel size and bruto/neto areas are also calculated here. So if you use bruto areas in Production Counts, you need to wait for this operation.

  • Each part of the IFC is analyzed, generating drawings and metadata which are saved in the database. This gives fast access to the information when the user clicks on a part in the 3D viewer.

  • Drawings are only generated for wood and plate parts, and for parts in custom branches marked for logistics in the IFC Parsing Setup. So, if your IFC Parsing Setup is incomplete, some part drawings may be missing.
