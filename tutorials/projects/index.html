Upload Files ​

Files for each project are uploaded in Files & Operations, in the project menu under Designs:

Click Upload. In the upload dialog, pick a file group first, and optionally a tipo, then drop, paste or browse the files and click Upload. The file group tells the system what the file is, and you choose it yourself. It starts on Assembly drawings (.pdf).

  1. The file group: what the files are. Pick it before you add the files.
  2. Drop, paste or browse the files. All of them get the group you picked.

The file groups are:

  • Assembly Files: Assembly IFCs (.ifc), Extra Assembly IFCs (.ifc), Assembly drawings (.pdf), Machine Files (.jjs, .wup, .btl).
  • Module Files: Module IFCs (.ifc), Extra Module IFCs (.ifc), Module drawings (.pdf).
  • Project Files: Project IFCs (.ifc), External IFCs (.ifc), Project drawings (.pdf).
  • Details and documentation: Details (.pdf), Documentation (.pdf, .jpeg, .png), Specifications (.pdf, text). Documentation and specifications can also be added as text with the Add as text switch.

The file name decides which design a file belongs to:

  • IFCs: used for the 3D viewer, BoMs and machine files. The system reads them with the project's IFC Parsing Setup. The file name without extension is the design name. Example: "PNL30-25.ifc" belongs to design "PNL30-25".

  • Extra IFCs: the design name is the part before the first " - ". Example: "PNL30-25 - Installations.ifc".

  • Machine files: the file name without extension is the design name. Example: "PNL30-25.btl".

Full Project IFCs

You can also upload full project IFCs and the system can split them into one IFC per design. Upload them in the Project IFCs (.ifc) group. The file name does not matter. Example: "OlaraAvenue15.ifc".

  • Drawings: .pdf file format. They are shown in the viewer. Drawing file names must follow the format "Merk DESIGN_NAME - DRAWING_NUMBER - DRAWING_NAME.pdf". The word "Merk" at the start is optional. Example: "Merk PNL30-25 - 1 - Zone 0 MAIN VIEW.pdf". If a drawing name does not follow this format, the upload shows a warning.

  • Details and documentation: .pdf file format. Also shown in the viewer. The file name without extension is the detail name that the system looks for in drawings. Example: "V-12.pdf". Documentation files are linked to every design of the project.

Full Project PDFs

In design mode, the viewer shows a "General Arrangement" entry at the top of the list. It opens the full project IFCs in 3D and the drawings uploaded as Project drawings (.pdf), one button per drawing.

  1. The list filter set to Design.
  2. The General Arrangement entry.
  3. The designs, with their revisions. Older revisions are red.
  4. 3D and one button per project drawing.

Table of uploaded files ​

The table of files is shown below the upload summary. The summary counts the files, how many are linked to a design and how many name a design that does not exist, and shows the project's parsing setup with a link to change it.

  1. Upload and Operations.
  2. The summary: files, files linked to a design, and files that name a design that does not exist.
  3. The search and Only latest versions.
  4. The design of each file. A full IFC shows how many designs came out of it; an orange chip names a design that does not exist.
  5. The status tags, explained below.

Use Filename search to filter the table, and Only latest versions to hide older versions of files uploaded again with the same name. Select rows to delete, download or split several files at once. The Design column shows the design each file is linked to.

Each status tag has its purpose:

TagDescription
File is busy. An ongoing operation locked this file. It is unlocked when the operation ends. Files are also unlocked when you use Clean stuck jobs in the operations menu. A big operation can run for more than 1 hour.
This file has been successfully uploaded, and it can now be used in operations.
This file has already been scanned for details. It can be an IFC, a drawing, or a detail.
This full IFC file has already been split.
This file was already used in the design generation operation. If it is the newest version of its design, it is attached to the design.
The file is being split with Split selected files. The percentage updates while the split runs.
The split started with Split selected files failed for this file.

Operations ​

Once project files are uploaded, click Operations to open the project operations dialog. Each operation shows its last run and status, and has its own Launch button. Launch all runs Split, Generate designs and Detect details one after the other. The menu at the top right of the dialog has Clean stuck jobs, which marks unfinished operations as failed and unlocks busy files. Use it only when you are sure no operation is still running.

  1. The menu with Clean stuck jobs.
  2. Split full IFC.
  3. Generate Designs.
  4. Detect details.

Split full IFC ​

Full IFCs are split into one assembly IFC per design. The new files are added to the project as Assembly IFCs and can be downloaded. The split also stores the quantity of each design and the phases and batches found in the IFC, so they are available in Production Counts. How assemblies are found in the IFC depends on the IFC Parsing Setup.

The split is available when the IFC splitter module is enabled for your company.

Designs

Split full IFC will not create "designs". Run Generate designs afterwards.

Parameters

☑️ Split project .ifc's into assembly .ifc's Splits the files uploaded as Project IFCs.

☑️ Split module .ifc's into assembly .ifc's Splits the files uploaded as Module IFCs.

☑️ Resplit already split files Also splits files that were already split. Normally you don't check this.

☑️ Skip standard library design names Does not create IFCs for designs that already exist in the standard library.

If no file group is checked, the split does nothing.

You can also select Project, Module or External IFCs in the table and click Split selected files. This opens Split into hierarchy, a newer splitting engine (beta) that can split into modules, assemblies in modules and assemblies at project root.

Generate Designs ​

The system collects the IFCs, drawings and machine files of the project and creates "design" objects.

  • A list of design names is built from the file names of assembly and module IFCs, drawings and machine files.

  • Each file is attached to its design. All the documentation files are linked to every design, so they are always available.

  • When a design gets new files, it gets a new revision.

Parameters

☑️ Keep current revision numbers Designs do not get a new revision number, even if new files were uploaded.

☑️ Generate elements in phase/batch Creates one unit of each new or changed design in the phase and batch you enter. Left empty, they are "Phase_1" and "Batch_1".

☑️ Generate drawings from IFC Generates drawings from the IFC of each design, with the default set of views.

Detect details ​

Details can be automatically detected in IFCs and PDF drawings. Found detail names are linked to the design and then shown in the viewer.

Parameters

☑️ Scan IFC files IFCs are scanned for detail names in the property "DET_NUMBER". Found names are linked to the design.

☑️ Scan PDF files Drawings are scanned to find detail and specification names, and details are scanned to find specification names. Found names are linked to the design. This option is checked by default.

If your detail names can't be detected by the system, you may have a rasterized export, or a rasterized font in a vectorized export, such as the well known issue with AutoCad.

Analysis (prepare the viewer) ​

The analysis starts automatically when a design gets a new IFC, for example after Generate designs. There is no button for it in the operations dialog. If the company setting Launch analysis automatically is off, or you need to run it again, select the designs in Designs and click Force analysis. The Analysis column of the designs table shows the status of each design.

Slow task!

⚠️ This operation takes time. It runs many heavy computations and database tasks.

  • IFC geometry is analyzed to find the rotation and translation matrices (orientation of the panel in the world coordinate system).

  • Panel size and bruto/neto areas are also calculated here. So if you use bruto areas in Production Counts, you need to wait for this operation.

  • Each part of the IFC is analyzed, generating drawings and metadata which are saved in the database. This gives fast access to the information when the user clicks on a part in the 3D viewer.

  • Drawings are only generated for wood and plate parts, and for parts in custom branches marked for logistics in the IFC Parsing Setup. So, if your IFC Parsing Setup is incomplete, some part drawings may be missing.
